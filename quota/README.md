# quota

`make test` 跑自检。

## 资源隔离判据

每个特效实例持有**独立的粒子池**（自有存储，他实例不可见）和**配额 q_i**（实例 i 任意时刻最多持有的粒子数）。不变量：

- 任意时刻 Σq_i ≤ G（G = 256 为全局上限）
- 任意实例 o_i ≤ q_i（占用不超配额，超出时淘汰本实例最新粒子）

新增实例只触发全量重算配额，不触碰他实例已有粒子 —— 这就是"后加特效清掉前面粒子"的修复点（`adding_instance_keeps_particles` 回归测试）。

## 配额函数与上限证明

配额是实例数 n 与占用向量 o_i 的函数（β 为地板保留比例，取 0.5）：

```
r(n) = ⌊βG/n⌋                    每实例保底地板
R(n) = G − n·r(n) ≥ (1−β)G        可分配余量（含取整零头）
u_i  = max(0, d_i − o_i)          实例 i 的未满足需求
q_i  = r(n) + ⌊R(n)·u_i / Σu_j⌋   （Σu = 0 时无额外分配）
```

**证明（任意 n ≥ 1、任意占用向量）**：向下取整只会缩小每一项，故

```
Σq_i ≤ n·r(n) + R(n)·(Σu_i/Σu_j) = n·r(n) + (G − n·r(n)) = G  ∎
```

`quota_sum_within_cap` 对 n = 1..64、β ∈ {0, 0.5, 1}、随机需求与占用做了穷举验证。

## 取舍：两条曲线定 β

- β = 0（纯按需）：大特效丢弃率最低（0.59），但小特效比例份额 ⌊256·1/560⌋ = 0，**全部饿死**（48/48）。
- β = 1（均分）：饿死率为 0，但大特效只有 G/n 配额，丢弃率 0.88 不可用。
- β = 0.25 是拐点：地板 ⌊64/64⌋ = 1 刚好覆盖小特效需求，饿死率归零，代价仅 0.3pp 丢弃率。
- 选 **β = 0.5**：拐点之上留一档余量 —— N=64 时地板为 2（容忍小特效需求翻倍），且 N 扩到 128 地板仍 ≥ 1；代价是大特效丢弃率从 0.60 升到 0.69，可接受。

```
curve beta=0.00 big_drop=0.593 small_starve=1.000
curve beta=0.10 big_drop=0.593 small_starve=1.000
curve beta=0.25 big_drop=0.596 small_starve=0.000
curve beta=0.50 big_drop=0.689 small_starve=0.000   <- 选用
curve beta=0.75 big_drop=0.782 small_starve=0.000
curve beta=1.00 big_drop=0.875 small_starve=0.000
```
