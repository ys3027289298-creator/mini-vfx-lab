# pause

暂停 / 恢复时的时间戳与发射量问题：恢复瞬间粒子“瞬移”、发射量一帧倾泻。
本目录用确定性脚本时钟复现、测量并验证修复，不依赖真实 sleep。

```sh
make test      # C 复现 + 21 项断言，同时重录 recordings/*.csv
make analyze   # Python 独立读 CSV 重新测量、拆分、验收（仅用标准库）
```

结果：C `all_ok=1`，Python `py_all_ok=1`。完整数字见
[`recordings/analysis_report.txt`](recordings/analysis_report.txt) 与
[`recordings/metrics.json`](recordings/metrics.json)。

## 1. 脚本与时间线（同一段操作，五个变体回放）

- 帧步长 `H = 1/60 = 0.016667s`，粒子速度 `v = 2.0 u/s`（匀速，距离可精确核对）。
- 第 1–30 帧正常运行；第 30 帧后暂停 `P = 1.0s`，期间第 31–90 个 wall tick
  照常产生、时间戳照走，但不推进模拟；第 91 帧恢复；之后 120 帧收尾。
- Bug 写法用的是**陈旧的“上次模拟时间”**做差，恢复帧一口吃到

  ```
  raw_dt = t91 - t30 = 61H = 1.016667s = H(0.016667) + P(1.000000)
  ```

同一个 `raw_dt` 同时喂给了 (a) 粒子积分和 (b) 发射器的 `rate_acc`。

五个变体：`buggy_full`（两处都用 raw_dt）、`time_only`（只保留时间补偿）、
`emit_only`（只保留发射累积倾泻）、`fixed`（本方案）、`scheduled`（完全不暂停的理想排班参照）。

## 2. 先录轨迹、量跳了多远

`recordings/traj_*.csv` 记录 12 个标记粒子的逐帧轨迹，并在第 30 / 91 帧做全量快照；
`frames_*.csv` 记录每帧 dt、发射数、欠账余额和**全粒子**最大单步位移。

标记粒子 id 0 的原始记录（x 坐标）：

```
buggy_full f29:(0.9667) f30:(1.0000) f91:(3.0333) f92:(3.0667) ...
fixed      f29:(0.9667) f30:(1.0000) f91:(1.0333) f92:(1.0667) ...
```

| 指标 | 数值 |
|---|---|
| 单帧正常位移 `J0 = v·H` | **0.033333** |
| Bug 恢复边界跳变 `Jbug = v·raw_dt` | **2.033333**（≈61 倍正常帧） |
| 超出正常帧的异常量 `X = Jbug − J0` | **2.000000** |
| Bug 恢复帧发射数 | **61**（1 常规 + 60 暂停欠账），稳态为 1/帧 |

## 3. 把这距离拆成「时间补偿」与「发射补发」

### 口径 A：消融实验，对“同一条已有轨迹的跳变”做加性拆分

每次只保留一个病因，重放同一脚本，边界最大同 id 跳变：

| 变体 | 边界跳变 | 相对 J0 的异常量 |
|---|---|---|
| `buggy_full` | 2.033333 | X = 2.000000 |
| `time_only`（raw_dt 只驱动运动） | 2.033333 | **+2.000000** |
| `emit_only`（运动只用 H，发射仍按 raw_dt 累积） | 0.033333 | **0.000000** |
| `fixed`（两者都修） | 0.033333 | 0.000000 |

恒等式 `X = X时间 + X发射 + X交互` 实测
`2.000000 = 2.000000 + 0.000000 + 0.000000`（交互残差 < 1e-4）。

**就“已有粒子轨迹上那一下位置跳变”而言：时间补偿占 100%，发射补发占 0%。**
这不是漏算发射——本仓库的更新顺序是“先积分旧粒子、后生成新粒子”，新粒子
`age=0` 且出生帧不再移动，所以一次性补发不会移动任何已存在粒子；它的空间代价
是另一种形态（口径 C），计数代价是 61 个/帧的倾泻。

### 口径 B：按 raw_dt 的帧构成拆 2.0333 这一跳

正常帧部分 `v·H = 0.0333`（占原始跳变 1.64%）；暂停段时间补偿
`v·P = 2.0000`（占 98.36%）；发射补发对同 id 位移贡献 `0`。

### 口径 C：暂停段的“空间欠账”两本账 —— 时间补偿 / 发射补发各占多少

暂停 1s、速度 2 定义了一段空间间隔 `G = v·P = 2.000`：

- **时间补偿（多走的账）**：旧粒子在恢复帧被赶着一步跨过整个 `G`，
  实际多跳 **2.000 u**。
- **发射补发（欠走 / 被抹平的账）**：60 个本应分布在暂停期出生的粒子被压成
  恢复帧同点、`age=0`。与 `scheduled` 理想排班按 id 逐一对比恢复帧位置：
  最老一个欠账粒子差 **2.0000 u**，60 个平均差 **1.0167 u**。

因此暂停造成的两本最大空间账合计 `2G = 4.000 u`，
**时间补偿 2.000（50%）、发射补发 2.000（50%）**。一个是“多走”，一个是
“欠走被抹平”，方向相反，不能混进同一条粒子线段里，但都是这次暂停的空间后果。

### 口径 D：同一条“粒子质心轨迹”跳变向量的严格拆分（交叉验证）

对 `buggy_full` 第 30→91 帧的质心跳变，用
`ΔC = N/(N+1)·ΔH + N/(N+1)·ΔP + 60/(N+61)·(E−C…)` 做望远镜拆分，
Python 直接从 CSV 读数计算，预测向量和与实测量完全一致（误差 < 1e-4）：

```
N_old=42, K=61(正常1+欠账60)
正常帧向量   +0.017885
时间补偿向量 +1.953488
发射欠账向量 -1.515918   (新粒子在原点 E，把质心往回拉)
实测质心跳变 +0.455455   (= 三项向量和，方向相反所以净额较小)
按两病因毛额 |1.953|+|-1.516|=3.469 计：时间 56.3% / 发射 43.7%
```

## 4. 修复：两条互不相通的账本

冲突的根源是**同一个 `dt` 被两个消费者绑定**：不把 `P` 喂给 `dt`，
`rate·P` 就记不进发射量（发射消失）；喂了，位置/年龄也会跟着吃 `P`（瞬移）。
解法是把“暂停了多久”同时结算成两个不同性质的量，各走各的账本：

1. **积分时钟（不能补的时间）——重定基，不补偿。**
   `PClock` 在每个 wall tick（包括暂停 tick）都刷新 `last_wall`。恢复时
   `sim_dt = now − last_wall` 恰好是一个 `H`；暂停跨度由 `pause_start`
   另外量出 `span = last_wall_at_last_pause_tick − pause_start = P`。
   `P` **永不进入**位置、速度、`age`、`tr_age`。防御性做法还可对 `sim_dt`
   设上限（处理卡顿/断点拖帧），本脚本时间线里重定基已给出精确的 `H`。

2. **发射账本（不能丢的数量）——记成粒子欠账，按上限摊还。**
   在恢复边界把 `rate·P = 60` 记入独立的 `debt`（整数）+ `debt_frac`
   （小数零头保留，不被 `int` 截断抹掉）。它是“欠多少个粒子”的标量，
   **不是 `dt`**，不参与任何积分。每帧在正常 `rate·H = 1` 配额外最多还
   `pay_cap = 1` 个欠账（总发射 ≤ 稳态 2 倍）：

   ```
   frame 91 恢复：spawned=2 (normal 1 + debt 1)，debt=59
   frames 91–150：每帧 2 个、debt 每帧 -1，第 150 帧 debt=0
   frame 151 起：回到 1/帧
   ```

**为什么两条约束不打架：**

- 丢掉积分时钟里的 `P`，并不会删掉发射账本里的 `rate·P`——后者在恢复边界
  由独立的 `pause_start` 结算，不依赖那个被丢掉的 `dt`。
- `debt` 只决定“何时出生几个粒子”；每个还债出生的粒子 `age=0`，此后只吃
  正常 `H`，所以补发不会变成任何粒子的大位移。它改变的是**出生排期**，
  不是已有轨迹。
- 两条账本只在同一帧各自结算，没有共享的时间增量，因此“不补时间”和
  “不丢发射量”可以同时成立。
- 容量池满时，欠账通过既有的 `dropped` 计数显式核销，而不是静默消失；
  本实验容量充足，`dropped=0`。

同样的原语已落到 `emitter` 模块：新增
`em_update_ex(e, dt, rate, burst, pause_span, pay_cap)`，原 `em_update`
变为 `em_update_ex(..., 0, 0)` 的包装，行为与既有断言完全不变；
`trail` 模块补了对照检查：把 `61H` 原始间隔喂给 `tr_age` 会清空整条轨迹，
而重定基后的 `H` 不会。
