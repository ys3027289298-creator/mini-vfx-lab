# splash

地面落地判定、溅射二次发射与带上限的共享粒子池。

## 问题背景

修复前雨滴没有任何地面判定：粒子更新只做积分和寿命过期，雨滴穿过
y = 0 继续下坠，直到寿命耗尽才消失（诊断实测坠到 y ≈ −138 m），
表现为"落地没有溅射，直接没了"。属于**判定缺失**，不是判定位置偏移。

## 实现要点（src/splash.c）

| 机制 | 做法 |
|---|---|
| 落地判定 | 线段-地面穿越：用上一位置 y 与本帧位置 ny 求穿越比例 t，插值出撞击点 x，撞击点钳制在 y = 0，不会因帧步长穿透 |
| 防穿透 | 物理子步固定 5 ms（`PHYS_H`），20 m/s 的雨滴单子步位移仅 0.1 m |
| 二次发射 | 每次雨滴落地在撞击点向上半平面发射 6 个溅射粒子（随机角度/速度，带阻力与重力） |
| 出生帧冻结 | 新粒子 `fresh` 标记，本帧不积分（与 emitter 模块"先推进后发射"约定一致） |
| 总池上限 | `POOL_MAX = 256`，雨滴与溅射共享，死槽位回收复用，满池丢弃并计入 `dropped` |
| 溅射上限 | `SPLASH_BUDGET = 48` 个溅射粒子同时存活，超出的爆发尝试直接拒绝并计入 `splash_dropped`，池子永远不会被溅射撑爆 |
| 链式开关 | 默认溅射粒子落地只销毁不二次发射；`stress` 模式开启 `splash_chain` 用于压测 |

自测 17 项：`make test`。

## 运行模式

```
./splash selftest
SPLASH_OUT=<dir> ./splash diag_baseline 0.1      # 无判定，复现 bug
SPLASH_OUT=<dir> ./splash diag_fixed    0.1      # 有判定
SPLASH_OUT=<dir> ./splash run    0.033 600 30 42 # 常规：30 滴/秒
SPLASH_OUT=<dir> ./splash stress 0.033 600 120 7 # 压力：120 滴/秒 + 链式
SPLASH_OUT=<dir> ./splash single 0.033 42 30     # 30 次独立落地，密度分析用
```

每个模式写出 `rain_trace.csv`（逐帧轨迹/消失事件）、`splash_trace.csv`
（撞击点）、`series.csv`（每帧池占用与计数）、`density.csv`（全部粒子位置）。

## 诊断结论（数据见 ../artifacts/）

1. **判定没做，不是位置偏了**：基线雨滴在帧 7 越过 y=0 后继续下坠，
   帧 39 于 h = −138.4 m 才因寿命过期消失；修复版同一雨滴帧 7 精确
   停在 h = 0 并产生撞击事件。
2. **密度随距离衰减**：30 次独立落地、4833 条采样的环形面积归一化密度，
   Spearman 秩相关 −0.94；近场峰 1.50 个/m²/落地/帧，中段存在弹道滞留
   平台（≈0.27），2.5 m 外快速归零，近场/远端相差约 7000 倍。形状不是
   纯指数律（指数参考线 R²=0.65，86% 的相邻环递减）。
3. **池子不会被撑爆**：常规场景峰值 74 粒子、压力场景峰值 145，均远低于
   256 上限；所有丢弃都来自 48 个的溅射预算（雨滴零丢弃）。压力场景
   丢弃 14031 > 实际发射 3423，因为丢弃统计的是**被预算拒绝的发射尝试**
   （2513 次撞击 × 每次 6 个），不是存活粒子。
